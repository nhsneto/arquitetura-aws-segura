AWS Cloud Defesa em Profundidade Zero Trust

Documentação dos Fluxos de Comunicação

Projeto: Arquitetura Cloud Segura Região: sa-east-1 (São Paulo) VPC: 10.0.0.0/16 Artefato: fluxos.pdf

1. Visão Geral e Topologia de Rede

A arquitetura foi projetada para atender integralmente aos requisitos de isolamento, resiliência e confidencialidade. Nenhum componente interno possui endereço IP público ou rota direta de entrada pela Internet. Toda a infraestrutura está contida em uma Virtual Private Cloud (VPC) com CIDR 10.0.0.0/16, dividida em três camadas estruturadas e distribuída em duas Zonas de Disponibilidade (sa-east-1a e sa-east-1b):

  • Sub-redes Públicas (10.0.1.0/24 e 10.0.2.0/24): Hospedam exclusivamente o Application Load Balancer (ALB) protegido pelo AWS WAF e conectado ao Internet Gateway (IGW).
  • Sub-redes Privadas de Aplicação (10.0.11.0/24 e 10.0.12.0/24): Hospedam as instâncias EC2 da API Backend e o endpoint do AWS Client VPN. Sem IP público e sem rota para a Internet.
  • Sub-redes Privadas de Dados (10.0.21.0/24 e 10.0.22.0/24): Hospedam o cluster Amazon RDS MySQL Multi-AZ (Primário na AZ-a e Standby na AZ-b). Isolamento completo.
  • Conectividade Privada com Serviços AWS: Todos os acessos ao Amazon S3, AWS Secrets Manager, AWS KMS e CloudWatch trafegam por VPC Endpoints (Gateway e PrivateLink), dispensando NAT Gateways para a internet.

4. Especificação Detalhada dos Security Groups

1. app-prod-alb-sg (Camada de Borda / Entrada Pública)
• Ingress: TCP 443 de 0.0.0.0/0 (HTTPS público seguro); TCP 80 de 0.0.0.0/0 (apenas redirecionamento 301 para 443).
• Egress: TCP 3000 com destino restrito ao identificador do grupo app-prod-api-sg.
2. app-prod-api-sg (Camada de Aplicação / Processamento)
• Ingress: TCP 3000 originado unicamente de app-prod-alb-sg; TCP 22 restrito ao CIDR administrativo de app-prod-vpn-sg.
• Egress: TCP 3306 destinado a app-prod-db-sg; TCP 443 destinado a app-prod-vpce-sg; TCP 443 destinado à Prefix List do S3.
3. app-prod-db-sg (Camada de Dados / Persistência)
• Ingress: TCP 3306 originado unicamente de app-prod-api-sg; TCP 3306 condicional de app-prod-vpn-sg para tarefas de administração.
• Egress: Sem regras amplas de saída. Apenas tráfego de resposta às consultas (natureza stateful) e replicação interna Multi-AZ.
4. app-prod-vpce-sg (Camada de Serviços Gerenciados AWS PrivateLink)
• Ingress: TCP 443 originado estritamente de app-prod-api-sg (Secrets Manager, KMS, CloudWatch Logs e SSM).
• Egress: Resposta às chamadas de API internas das interfaces elásticas privadas (ENIs).
5. app-prod-vpn-sg (Camada de Acesso Administrativo e Manutenção)
• Ingress: UDP/TCP 443 a partir de endereços administrativos na internet mediante autenticação forte e MFA.
• Egress: TCP 443 (SSM) e TCP 22 para app-prod-api-sg; TCP 3306 para app-prod-db-sg sob regra de autorização explícita do Client VPN.

5. Detalhamento dos Fluxos Operacionais Fim a Fim

Fluxo A: Requisição Web Segura do Usuário e Processamento

  1. Iniciação da Sessão: O usuário envia uma requisição HTTPS para o domínio corporativo. O DNS resolve o alias para os IPs elásticos do ALB nas sub-redes públicas A e B.
  2. Filtragem no WAF: O AWS WAF intercepta a requisição e valida a assinatura contra regras gerenciadas da AWS (reputação de IP, mitigação de SQLi, XSS e flood rate-limiting). Se maliciosa, a conexão é descartada com código 403 Forbidden.
  3. Término TLS e Distribuição: O ALB desembala a conexão TLS com o certificado emitido pelo AWS Certificate Manager (ACM) e escolhe um nó íntegro de API com base no algoritmo de balanceamento.
  4. Comunicação Interna Segura: A requisição é encaminhada na porta TCP 3000 para a instância EC2 na AZ privada correspondente. O app-prod-api-sg autoriza o pacote por reconhecer o ID do SG do balanceador.

Fluxo B: Conexão Segura ao Banco de Dados Relacional

  1. Autenticação sem Senhas no Código: A API invoca o AWS Secrets Manager através do Interface VPC Endpoint (TCP 443) utilizando credenciais temporárias obtidas via sua IAM Role de instância.
  2. Abertura de Conexão: A API obtém a string e credenciais e estabelece conexão TCP na porta 3306 com o endpoint do RDS MySQL.
  3. Isolamento Físico e Lógico: O pacote trafega estritamente dentro da VPC até a sub-rede privada de dados. O app-prod-db-sg permite a entrada do tráfego unicamente porque a origem é o app-prod-api-sg.
  4. Replicação Automática: Concomitantemente, qualquer transação de escrita é sincronizada de modo síncrono com a instância Standby na AZ-b, mantendo réplica idêntica sem expor portas adicionais.

Fluxo C: Upload e Armazenamento Privado de Arquivos (Amazon S3)

  1. Recepção do Objeto: O usuário envia um arquivo através da API.
  2. Roteamento via Gateway Endpoint: A instância EC2 faz um PutObject na API S3 (https://s3.sa-east-1.amazonaws.com). A tabela de rotas da sub-rede privada intercepta o CIDR do S3 e desvia o tráfego para o Gateway VPC Endpoint (vpce-s3), mantendo o pacote dentro da infraestrutura interna da AWS sem tráfego de internet.
  3. Validação de Políticas de Segurança: O S3 valida que o S3 Block Public Access está 100% habilitado e a Bucket Policy exige que a chamada se origine do identificador específico do VPC Endpoint da empresa.
  4. Criptografia em Repouso: O objeto é gravado com cifragem no lado do servidor utilizando chave gerenciada pelo cliente no KMS (SSE-KMS), garantindo controle total sobre quem pode decriptar os dados.

Fluxo D: Manutenção Administrativa Segura e Auditoria

  1. Túnel Criptografado com MFA: O operador administrativo conecta-se ao AWS Client VPN na porta 443, passando por verificação multifator obrigatória.
  2. Acesso sem Portas Abertas (AWS SSM): O administrador gerencia os servidores EC2 prioritariamente através do AWS Systems Manager Session Manager, que encapsula comandos via canal TLS protegido por IAM, dispensando chaves SSH e eliminando a necessidade de Bastion Hosts.
  3. Trilhas e Rastreabilidade Total: Todas as ações administrativas são registradas no AWS CloudTrail (quem realizou, quando, de qual IP e qual parâmetro foi enviado). As sessões de terminal podem ser gravadas em buckets S3 com retenção imutável.
  4. Monitoramento de Rede: O VPC Flow Logs captura dados de todas as conexões permitidas e rejeitadas, enviando os eventos para o Amazon CloudWatch Logs com alertas configurados para picos de conexões negadas.

6. Conformidade com os Requisitos do Projeto

A solução atende rigorosamente a cada uma das diretrizes formuladas na proposta acadêmica:

  • Requisito 1 (HTTPS obrigatório): Tráfego externo TLS/HTTPS 443 obrigatório no ALB, com redirecionamento de HTTP 80 para HTTPS.
  • Requisito 2 (Proteção e distribuição de tráfego): AWS WAF associado ao ALB para proteção L7 e distribuição de carga com alta disponibilidade.
  • Requisito 3 (Processamento seguro na API): Instâncias EC2 em sub-redes privadas sem IP público, comunicando-se internamente com recursos restritos.
  • Requisito 4 (Banco de dados inacessível publicamente): RDS MySQL em sub-redes privadas dedicadas, sem rota pública e com acesso exclusivo pela API (3306).
  • Requisito 5 (Armazenamento controlado de arquivos): Bucket S3 com Block Public Access ativo, acessado privadamente via Gateway Endpoint e protegido com SSE-KMS.
  • Requisito 6 (Acesso administrativo seguro): AWS Client VPN com autenticação MFA e gerenciamento sem chave SSH via AWS Systems Manager.
  • Requisitos 7 e 9 (Menor Privilégio e Comunicações Mínimas): Security Groups encadeados por ID de grupo, ausência de regras abertas para a Internet e IAM Roles temporárias.
  • Requisito 8 (Auditoria e monitoramento contínuo): CloudWatch Logs e Métricas, CloudTrail para trilhas de governança e VPC Flow Logs em todas as ENIs.
